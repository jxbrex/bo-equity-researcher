# v0.16.0-handoff — 1D 九项与杜邦四因子 TTM 口径整改

## 1. 本版改动

1. **唯一 TTM 计算层**：`em_finance.compute_ttm_metrics`（纯函数、零 I/O），1D 九项的 ROA 改善/资产周转改善与 4.6 杜邦四因子共用同一份终态输出。TTM 流量=去年全年−去年同期累计+本期累计；平均存量=（上年同季末+本季末）÷2（年报期=年初年末均值）；ROA 用含少数股东净利、杜邦三因子用归母口径（nm×em×turnover=roe 浮点容差内闭合）。
2. **杜邦四因子改 TTM 口径**（落盘/fill 携 `basis:"ttm"`、`prev_period`），东财 F10 降为对账源：同报告期累计营收/归母与 tushare 差异超 1% 容差 → 判重述冲突，四因子不输出（不静默生成混合口径乘积链），原因进 `dupont.issues`；另落盘同公式年度 `history` 序列仅供对账、不渲染。
3. **口径门禁与 legacy 边界**：fill 与落盘 dupont 皆无 basis=旧累计口径兼容展示；任一侧声明 ttm 而另一侧无/不同 → 拒渲染。旧 fill 重渲不受影响（不批量重渲）。
4. **空值三态与重述守卫**：tushare 同报告期同字段多值冲突 → 该期该字段按缺失处理并留痕；缺期/非正分母一律缺失不猜数；短债/长债可独立缺失（不再单字段空导致全部归零）；九项明细表 TTM 项单独标注期间，叶级「未获取」可经 `manual_evidence`（source+note 双路径）补证，f_items 已判定而依据未获取则告警。
5. **文档与版本**：scoring.md 九项各自期间+TTM 公式+重述降级+legacy 边界，删除 1F 归因句「照抄 E3 年表手算净利率/负债率」旧条款；fill-schema/data-collection/data-sources/SKILL 清单同步；tasks/lessons.md 记录「流量期间须与平均存量匹配；空值三态；两处一致必须共享终态数据」。`RENDERER_VERSION` v0.15.0→v0.16.0，README/CHANGELOG 同步。**ROIC（仍为累计值线性年化）、OCF/短债、现金跑道本轮一律未改分。**

## 3. 本轮裁决与边界

- 用户明确授权当前 main 工作区；**本轮无任何 Git 写操作**（不 commit/push/tag/release/deploy，不归档旧 handoff——归档与发布全套待用户确认版本后按仓库固定顺序执行）。
- 盐湖重述冲突未获正式报表同口径证据 → **保留安全降级**，未用原始试算值冒充结论；若后续取得正式报表同口径数据，重跑 `em_fetch --out` 即可自动恢复四因子输出。
- **冲突适用范围裁决（终审增补）**：两类冲突不得混为一谈——tushare 同报告期内部多值冲突（调整前/后并立）→ 该期该字段缺失，涉该字段的 1D 指标随之缺失；东财 F10↔tushare 跨源冲突（累计营收/归母超 1% 容差）→ **只降级杜邦四因子**，1D 的 ROA 改善与资产周转改善仍是 tushare 单源 TTM、照常输出，不参与跨源混算。盐湖 000792 即按此裁决处理：杜邦四因子安全降级，但九项 TTM 机械读数（ROA 12.62%→25.17%、周转 0.314→0.404 次）有效、不丢弃——「盐湖机械 TTM 全部不出结论」是误读。成本是用户必须同时看到来源与适用范围，scoring.md/fill-schema.md/data-collection.md 已写清。
- 不批量重渲历史报告；legacy 旧 fill（无 basis）渲染行为不变。不新增依赖；未派发子代理。
- 盐湖验收副本（`fill_000792_ttm.json`）因无真实归档 fill，以同型周期股模板改造：机械数据/图表全部换成 2026-11-08 真实取数，subtitle 与 thesis 显著标注「验收副本、非研究报告」，九维正文按四要素重写（数据真实）；属隔离验收产物，禁止外发。
