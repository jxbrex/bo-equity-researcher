# v0.16.1-handoff — 妙想调用故障分类与本地嵌套恢复

## 1. 本版改动

1. **MCP 漏用不等于未暴露**：九州通会话主代理日志显示 11 个妙想 MCP 工具已发现并加载，主模型却零调用便误判“未暴露”。`data-collection.md` 工具探测改为只认实际工具快照与调用记录；已加载但未调用归为漏用，不得写成服务不可用。
2. **本地嵌套拦截单列**：主会话在既有三层技能上调用 `mx-data`，被 Skill 工具以 `maximum depth of 3` 拦截，请求未触及妙想 API。`SKILL.md` 新增强制恢复：停止嵌套主会话重试，将未完成查询委派给未加载其他技能的干净子会话；子会话仍按 MCP 优先、对应 mx skill 接力，只有恢复路径也实际确认两级不可用才允许降级标注。
3. **文档同源**：详细规则只在 `references/data-collection.md`，`SKILL.md` 与 `references/data-sources.md` 保留一致摘要和指针；`tasks/lessons.md` 记录九州通实证。普通网络失败、空结果、未指明额度耗尽的限流及 429 硬停规则不变。
4. **版本边界**：发布编号 v0.16.0→v0.16.1；`RENDERER_VERSION` 保持 v0.16.0。无 Python、模板、评分、字段、依赖或历史报告改动。

## 2. 验证证据

- 原会话主代理 `wire.jsonl`：工具发现与加载记录均含 11 个 MCP 工具；主会话 MCP 调用数为零；`mx-data` 的错误为本地 `Nested skill invocation ... maximum depth of 3`。干净子会话 MCP 直调成功，证明原事件不是服务、网络或额度故障。
- 妙想 skill 在干净子会话中未另行实测，因为 MCP 已成功；不宣称“skill 已恢复验证”。
- 正式九州通报告已使用补得的 MCP 数据，无“双通道不可用”或嵌套错误残留，不重渲。
- 全量 `python -m pytest scripts/ -q` 两次均 **830 passed**（含既有 golden）；`git diff --check` 无空白错误。
- 独立只读终审无 Critical/Important；其指出的两处“mx skill 返回”措辞已统一为“Skill 工具返回”，随后全量测试再次通过。

## 3. 本轮裁决与边界

- 本版只修执行规则文档，不能机械保证宿主模型未来一定选择正确工具；不修改 Kimi Code 最大嵌套深度，也不把所有妙想查询永久改为委派。
- 主会话局部编排失败不得写成妙想服务故障；只有实际调用与必要恢复均确认两级不可用，才可走降级链并作报告标注。
- 九州通报告本体不因本次工具事故重渲；其他数据或分析疑问另立项。
- 旧议题由 v0.16.0 全量结转，未因本版文档修订自动销账。
