# 报告质量系统性根因整改设计

## 意图与背景

近期多份报告在测试、预检和视觉检查全绿后，仍由用户实读发现错分、漏图、正文缺项、卡片归位错误和跨章口径冲突。继续按单点事故增加校验，会让规则越来越长，却没有提高交付可靠性。

本次只读复盘了八个近期维护会话及其指向的原始报告会话，确认五个共同根因：

1. “合格报告”的目标、契约与交付口径不一致，四要素曾被误交付为三要素。
2. 同一事实在评分、图表、三情景和正文中重复手填，逐处修改必然产生组合矛盾。
3. `--check` 停在正式渲染前，最终 HTML 的读者级内容缺少完整门禁。
4. 官方快照来自合成 fill，完整真实事故没有形成标准验收集。
5. 软告警和反复返工激励生成方删预测、合并年份、收窄区间来消警，而不是回查事实。

## 方案取舍

采用“真实事故回归 + 最终成品门禁 + 增长链单一事实来源”的纵向小切片。

- 不采用只增加独立终检：它能发现部分问题，但不能消除重复填参和错误规则。
- 不采用全量重写：当前约 240 个软告警和大量历史 fill 使全量改造的回归风险过高。
- 选择增长链作为试点，因为比亚迪、益丰、工业富联已反复证明其跨字段矛盾会改变评分和读者判断。

## 目标

- 历史严重问题成为可重复执行的检测题。
- `--check` 在写盘前完成最终 HTML 的内容与完整性检查。
- 新报告明确利润所属年份，同一年的评分增速、增长图和预期差利润只由一个假设计算。
- 交付证据同时列明历史事故拦截结果与真实整案验收结果。

## 非目标与反目标

- 不全量重写校验，不把风格提示一概升级为拒渲染。
- 不批量重渲或重评历史报告，不调整评分阈值、行业权重和估值方法。
- 不在同版新增图表、排版或数据接口。
- 不以测试数量、快照无变化或子智能体全绿结论代替真实报告验收。
- 不开发猜测“删预测/消警行为”的泛化识别器。

## 已确定的实现决策

### 真实事故集

从事发会话的 transcript/file-history 和 `D:/个股深度分析/_archive/` 取得原始证据，不用事后重建夹具冒充真实事故。比亚迪、中免、益丰、工业富联、金诚信、中国船舶均登记根因与不变量；至少比亚迪、中免、益丰完成真实整案验收。无法完整恢复的样本只保留可核验的最小反例，并明确标注。

原文件只读，所有生成物进入 `artifacts/_quality_root_cause/`。坏样本的绿色含义是“被检测器拦截”，不是“可以直接交付”。

真实语料由独立脚本检查，路径显式传入，不在 pytest 中硬编码本机目录。核心检查由常规 pytest 覆盖，外部语料只作为本地发布门槛。

### 最终成品门禁

将当前 `render()` 的完整内存渲染路径供 `--check` 和正式写盘共用。预检也完成图表构建、模板合成和最终 HTML 校验，但不写报告、不归档、不移动证据。

新增门禁只覆盖明确不变量：九维块及四要素在注入后仍完整；契约要求出现的组件实际出现且只出现一次；`prev.charts` 声明的旧组件消失时有对应原因；最终增长数字等于规范化视图；所有最终校验在 `--check` 中执行。能复用现有函数的不得另写一套判定。

独立终检继续使用默认次一级子智能体、只读一轮、最多五条重要发现。为其提供去除 CSS/SVG 的最终正文和同一验收清单。

### 增长链单一事实来源

利润口径估值新增 `valuation.profit_year`，明确三情景利润所属年度；市值口径不要求。新报告必填，旧 fill 保留既有推断与迁移路径。

在 `_preflight` 与 `compute_scores` 可共用的入口生成规范化 fill 视图，不改写归档原文件。对 `profit_year` 对应年度：

- 由最近实际归母净利和三情景利润计算增速区间；
- 将区间提供给 3A 与 `growth_plot.fcst`；
- 将基础情景利润提供给该年 `gap_plot` 的本文净利值。

新报告不再手填这些派生值。用户已拍板：仍可自动计算的字段若被手填，直接拒渲染并指出应删除的重复字段；即使碰巧一致也不放行，更不静默覆盖。旧 fill 保留兼容校验。其他预测年度没有唯一事实来源的，不强行推算。

保留现有 3A 评分规则和三情景语义，只移除重复输入。非正分母、缺年份、重述不可比、共识年仅卖方数据等边界必须显式处理。

## 约束

- 遵循现有 Python 标准库、pytest、fill→render 工作流，不新增运行时依赖。
- 新门禁只拒事实矛盾、必要内容缺失和静默减配；风格与迁移提示保持原级别。
- 所有修复先用事故反例证明可复现，再做最小实现。
- 真实报告和会话证据只读，部署目录不读写。
- 未经用户确认，不 commit、push、tag、release 或 deploy。

## 验收标准

- 历史事故反例在修改前失败、修改后按预期被拦截或通过。
- 修改一个利润假设，3A、增长图和预期差同步变化；重复手填被明确拒绝。
- `--check` 能发现最终成品错误，失败时零写盘副作用。
- 至少比亚迪、中免、益丰三份真实整案完成隔离渲染与最终正文检查。
- 全量 pytest、官方 golden、代表性报告双视口检查通过。
- 独立次一级子智能体按同一清单终审，主会话核实重要发现。

## 留给实施者的事项

- 规范化函数与完整内存渲染函数的具体签名，按现有代码结构做最小拆分。
- 真实语料脚本名称和清单文件格式，保持简单、显式路径、无新依赖。
- 版本号按仓库下一版本确定；发布仍由用户另行拍板。
