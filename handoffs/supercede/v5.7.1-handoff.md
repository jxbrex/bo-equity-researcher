# v5.7.1-handoff — 妙想 skill 接力条件扩充：MCP 缺席或明确积分/额度耗尽双触发（纯文档版）

> 缘起：用户确认妙想 MCP 与 mx-* skill 使用相互独立的 API Key/额度，要求覆盖「工具在线但
> 积分耗尽」场景。基线规则测试显示旧规则只覆盖「缺席」，耗尽场景无法唯一选择下一数据源；
> 普通网络超时又不应切 skill。纯文档版：SKILL.md + data-collection.md + data-sources.md +
> scoring.md + CHANGELOG，零代码改动，`RENDERER_VERSION` 不变。回归：pytest **244 全绿**，
> golden 零变化。

## 本版改动（细则见 CHANGELOG V5.7.1）

- 妙想接力改双触发：MCP 工具缺席，或调用返回明确的积分/额度耗尽提示。
- 按用途映射：定量查数 → `mx-data`；定性检索 → `mx-search`；选股筛选 → `mx-xuangu`。
- 明确三不接力：普通网络失败、查询无结果、未指明额度耗尽的普通 429/限流——避免误消耗
  另一 Key。
- skill 也失败或额度耗尽后，才继续手工 curl / WebSearch / E7 等原降级链；两级均不可用时
  报告显式标注「妙想 MCP 与 mx skill 均不可用，已走降级路径」。
- scoring.md 三处补齐：现金含量、港股豁免、档位 B 研报检索均改为 MCP/skill 双通道；
  筹码分布按定量用途走 `mx-data`。

## 研讨历程要点（防重走弯路）

- **「工具在线」不等于「通道可用」**：旧规则把 skill 触发条件写成工具缺席，遗漏了 MCP 仍在
  工具列表但额度已耗尽的中间态。两个 Key 独立后，这不是同一通道重试，而是下一级数据源。
- **不能把 429 一律当成额度耗尽**：普通限流、网络失败、查询无结果都不该烧第二份额度；
  接力条件必须落在「明确积分/额度耗尽提示」这一可观察报文上。
- **本版仍是调度规则，不是脚本自动故障转移**：妙想通道保持模型直调层，不进 `em_fetch.py`；
  这次改的是 skill 层选择规则，不新增代码路径。
- 独立审查后修了 Minor：术语统一为「接力」，scoring.md 三处旧单通道表述补齐，CHANGELOG
  补版本号与文末标注点；历史 handoff 未回改。
